Lore is a local MCP server. The setup below connects it to Codex or Claude Code on Windows through Ubuntu WSL 2. Run one setup script in PowerShell, then ask for history in a new agent session.

1. Set up Lore

Before you begin

You need Windows with Ubuntu WSL 2 ready to run, and either the Codex CLI (codex) or Claude Code CLI (claude) available in PowerShell. This is an early developer preview, not a one-click installer for all Windows users. Follow Microsoft’s WSL guide if Ubuntu is not set up.

  1. Download Lore’s MCP server and the setup script for your agent: Codex or Claude Code. Save both files in the same new folder, such as Downloads\Lore.
  2. Open that folder in File Explorer. Right-click empty space and choose Open in Terminal, then select PowerShell if needed.
  3. Run your agent's setup command below. If your WSL distribution is not named Ubuntu, add -Distro YourName to the command.
  4. Open a new agent session in your project and use the request shown below.
.\install-codex.ps1
# Or, for Claude Code:
.\install-claude-code.ps1

If you use both agents, run both scripts. They share one local Lore archive.

For integrity checking, compare the published SHA-256 checksums. The setup script also verifies the server binary before it copies it. The package includes the Free Binary License and third-party notices.

Each script backs up the selected agent's existing configuration, installs Lore under your Windows user profile, and registers the local MCP connection. It does not delete your existing Lore archive. If PowerShell refuses to run a downloaded script, inspect it and follow a manual setup instead of turning off Windows protections.

2. Ask for history in your agent

Start a new session in the project folder, then type this in the Codex or Claude Code chat box:

Read the relevant history, then continue.

You can also ask a specific question, such as Through Lore, find why we chose this deployment approach. Your agent should call Lore’s tools and cite the messages it used. Ask it to say when evidence is missing or conflicting.

Lore automatically discovers accessible local Codex, Claude Code and Qwen Code session files when recalling. You do not need to import those local chats one by one. Its archive is stored at %USERPROFILE%\.lore\archive.json; no Lore account or hosted memory server is needed.

What this preview covers

This package was tested end to end with Codex and Claude Code on Windows through Ubuntu WSL 2. Other MCP clients can potentially call the same local server, but their setup and behavior have not yet been validated with this package. A model such as Ollama needs a separate MCP-capable host that actually calls tools.

Browser ChatGPT and Claude account histories are not automatically available just because Lore is connected. Cloud-only chats need a separate capture or import path. The older browser extension is not bundled with this MCP-only preview.

Lore retrieves relevant evidence from history it can access. It can miss context, and a chat statement is not independent proof that an email was sent or a deployment succeeded. Review cited sources before acting on important conclusions. There is no automatic sync between computers.

If something does not work

WSL says Ubuntu is missing or not ready.

Complete Microsoft’s Ubuntu WSL setup, launch Ubuntu once to finish first-run setup, and retry. If your distribution uses another name, pass it with -Distro.

The installer says the agent CLI is required.

Install or expose codex or claude in PowerShell for the script you chose, then retry.

PowerShell blocks the script.

Inspect the downloaded file and its checksum. Your policy may require manual setup. Do not disable Smart App Control, Defender, or workplace restrictions just to run Lore.

My agent asks me to paste old chats.

Start a new agent session after installation and explicitly say “through Lore.” Check that Lore appears in its MCP tools. The currently open task may still hold an older connection.

Lore finds the wrong project or misses a detail.

Open the agent in the intended project folder, ask a more specific question, and inspect the cited source. If a detail is absent from accessible history, Lore cannot recover it.

How do I report a problem?

Use the issue tracker. Include your Lore version, Windows/WSL version, client and a redacted reproduction; do not post private chat history or credentials.
