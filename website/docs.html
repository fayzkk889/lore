SETUP GUIDE

Install once.
Recall through your agent.

You run the setup commands in your computer’s terminal. After setup, you ask for memory in your AI client’s chat box. You don’t run import commands every time you start a new coding-agent chat.

1. Install Lore

Beta protection notices

Windows binaries and scripts are unsigned. Your OS or workplace policy may warn or block them. Keep security protections enabled. This launch supports Windows; other operating systems are deferred.

Windows

Open the Start menu, type PowerShell, and open it. Run these two lines:

Invoke-WebRequest https://raw.githubusercontent.com/fayzkk889/lore/main/install.ps1 -OutFile install-lore.ps1
.\install-lore.ps1

The installer downloads the matching release and verifies its checksum. Close and reopen PowerShell after installation so it can find lore.

Download archives and checksums directly if you prefer to inspect the files first.

2. Connect your coding agent

In your terminal, run:

lore connect

Lore connects the supported clients it detects. Restart your client afterward. To connect one client explicitly, run only its line below:

lore connect codex
lore connect claude-code
lore connect qwen
lore connect cursor
lore connect claude-desktop

If no client is detected, use one of the explicit client names above. Connecting Codex, Claude Code or Qwen Code installs managed default global guidance so history requests can discover Lore. Your existing guidance is preserved.

OpenCode requires manual MCP configuration. Ollama requires a client that executes tools; running an Ollama model by itself does not connect it to Lore. See the current client configuration documentation.

3. Ask in your chat box

In a fresh connected chat, try:

Read the relevant history and continue this work.

For an explicit request that names the tool:

Get the relevant project context from Lore.
Through Lore, find why we chose this deployment approach.
Remember this decision in Lore: use the existing payment handler.
Show my saved Lore memories for this project.

Lore discovers accessible local Codex, Claude Code and Qwen Code history during recall. Cursor and Claude Desktop use shared saved or imported memory; their own native chat capture is not automatic. A model must call the tool to retrieve context. Ask it to name missing evidence rather than invent details.

Memory lives locally at ~/.lore/archive.json by default. A different computer needs its own setup and an explicit memory transfer; there is no automatic cloud sync.

Browser project memory — developer preview

Not yet a browser-store release

The optional extension has been tested in Chromium against controlled ChatGPT/Claude layout fixtures. Authenticated live-site validation and store publishing remain pending. Use Windows alpha.7, which includes the browser host.

  1. Download the compatible Lore app and the extension preview from GitHub Releases. Extract the extension ZIP into a folder.
  2. Open chrome://extensions or edge://extensions. Enable Developer mode, choose Load unpacked, and select the extracted folder containing manifest.json.
  3. In your terminal, run lore browser install once.
  4. Open a saved ChatGPT or Claude conversation, click Lore’s toolbar icon, choose the matching project, and explicitly enable capture for that conversation.
  5. In a new browser chat, open Lore, choose the project, and click Get project context. Insert into an empty draft or copy it, then review and send yourself.
  6. In your coding agent, ask for relevant history through Lore. Choose an existing workspace in the extension for its default scope, or ask for a named project explicitly.

Capture covers opened, rendered messages rather than all account history. Stable-ID edits replace their saved turns. When a layout lacks message IDs, older edited versions can remain; the popup reports this. Browser timestamps are capture times, not original authored dates. Attachments and complete regenerated branches are not captured.

Updating the installed Lore executable at the registered path updates the memory engine used by the extension. Moving the app requires rerunning lore browser install. This unpacked preview requires manual updates for extension code; store-managed updates come after publication.

If something doesn’t work

“Lore” isn’t recognized in my terminal.

Restart the terminal after installation. If you installed into a custom folder without PATH changes, invoke the executable by its full path.

The agent asks me to paste a handoff.

Restart the client after connecting, then explicitly ask it to retrieve context through Lore. Confirm Lore’s MCP server appears in the client’s tools. On upgrade, run lore connect again to refresh its stable executable and guidance.

The extension says local Lore is unavailable.

Use a compatible app build, run lore browser install from its installed path, and retry. If you use a custom memory store, reconnect with --store pointing to the same archive as your coding agent. The error includes the browser’s connection detail.

Capture is enabled but I can’t find the history.

Check the extension’s saved status and selected project. Unsaved chat URLs, hidden/unloaded messages and changed layouts can prevent capture. A wrong workspace will retrieve different context. Pause does not delete previously saved history.

Windows blocks the download or executable.

Keep protections enabled. Report the exact message, Lore version, Windows version and client through the issue tracker. Don’t include private conversation history or credentials. A checksum verifies file integrity; it does not replace publisher signing.

I want to remove Lore memory or disconnect it.

Ask your connected agent to list memories and forget the specific cited conversation. Automatic browser capture respects forgotten records. Run lore disconnect --all to remove supported MCP connections. Consult the public uninstall scripts for removing the app; local memory remains unless you explicitly choose to purge it.
